# ADR-0001: Context first, verification later

- **Status:** Proposed
- **Date:** 2026-10-13
- **Phase:** foundation

## Context

The original draft was a fact-checking portal with verdicts. The goal grew into an interactive map that aggregates and contrasts news, traces events over five years and adds statistical and voter context. Both can share the same data, but they need different amounts of editorial work.

## Options considered

### Option A — Context first (chosen)
Aggregation, contrast and traceability come first; fact-check verdicts from the draft arrive in phase 6.
- Pros: Needs no editorial review to publish; verdict work builds on the same data; fits one or two people.
- Cons: Months of an informative portal that does not judge claims.

### Option B — Verification first
The draft as written.
- Pros: Clearer value proposition.
- Cons: No map or news until indicators and reviewers exist.

### Option C — Both at once
Build both from the start.
- Pros: Complete from the beginning.
- Cons: Scope too large for a small team.

## Decision

Context first. The author wants to aggregate, contrast and give traceability before judging claims. Verification is phase 6 on the same base.

## Consequences

- What gets easier: a first useful version without a review panel.
- What gets harder / what we accept: the draft's verdict scale and review workflow wait until phase 6.
- What would make us revisit this: if the first users ask mainly for verdicts
